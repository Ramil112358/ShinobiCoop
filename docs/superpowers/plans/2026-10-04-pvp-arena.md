# PvP Arena Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 1v1 and 2v2 best-of-3 arena fights (with bots filling empty slots and four power-up types) on four small maps cut from the four districts of `Lvl_London`, hosted from the session menu.

**Architecture:** `EShinobiTeam` gains `TeamA`/`TeamB` (replicated), so the existing `IsHostileTo` paths do PvP unchanged. A new `AShinobiPvpGameMode` runs a state machine whose decisions live in a plain, unit-tested struct `FShinobiPvpMatch`. Power-ups are replicated actors applying timed gameplay effects that `UShinobiDamageExec` and `UShinobiMovementComponent` read. Bots subclass the existing enemy AI. Maps come from `Scripts/london/build_arenas.py`, which reuses `build_london.py` with a chunk filter.

**Tech Stack:** UE 5.8 C++ (GameplayAbilities, OnlineSubsystem, UMG canvas HUD), UE automation tests (`Scripts/run_tests.ps1`), UE Python commandlets (`Scripts/run_python.ps1`), Python 3 with shapely/PIL for layout checks.

**Spec:** `docs/superpowers/specs/2026-10-04-pvp-arena-design.md`

## Review Focus

- A human disconnects or falls out of the world mid-round (pawn destroyed): the round must still resolve (that pawn counts as not alive), never hang. Test in Task 3.
- Both teams' last members die in the same tick: a Tie that replays, not a win for A. Test in Task 2.
- A pickup overlapped by two characters in one frame: applied once. Test in Task 5.
- Boosts, shield and held pickups must not leak across a round reset (tags cleared, pickups back). Test in Task 3 and 5.
- A third human tries to join a 1v1, or a joiner arrives mid-match: rejected / placed on the team with fewer humans, bots shrink next round. Test in Task 2/3.
- Timer expiry with nobody fighting (bots stuck without navmesh): the round resolves on the health comparison. Test in Task 2.
