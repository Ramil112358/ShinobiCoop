- [ ] **Step 1: Write `Scripts/setup_vfx.py`**

```python
"""Chakra charge aura materials. Idempotent: rebuilds both materials from scratch each run.

Close the GUI editor before running: an editor that has these materials loaded would silently
overwrite the regenerated assets on its next Save All.

M_ChakraAura (flame shells): upward-scrolling procedural noise flames, fresnel rim, soft top fade.
M_ChakraRing (ground ring): a ring pulsing outward plus a faint centre glow.
Both: unlit, additive, two-sided; parameters Color (vector), Intensity, Fade (scalars) driven by
UShinobiChakraAuraComponent.

Substrate routing (r.Substrate=True, confirmed against the 5.8 engine source):
UMaterialExpressionSubstrateUnlitBSDF's Emissive Color input is connected, then the BSDF node is wired
into the material's Front Material slot (unreal.MaterialProperty.MP_FRONT_MATERIAL). Unlit + additive
still uses MP_FrontMaterial exclusively in 5.8 (UMaterial::IsPropertyActive's Substrate branch for the
unlit shading model returns true only for MP_FrontMaterial), so no different route is needed.

Two pin names differ from the naive assumption, both confirmed against the engine source:
- UMaterialExpressionSubstrateUnlitBSDF does not override GetInputName(), so
  MaterialEditingLibrary.connect_material_expressions must target the raw FExpressionInput property
  name "EmissiveColor" (no space) -- not the doc-comment phrase "Emissive Color".
  UMaterialGraphNode::GetShortenPinName (which is what would otherwise turn a long pin name into a
  shorter display name, e.g. Coordinates -> UVs) only remaps a fixed list of special-cased names and
  EmissiveColor is not one of them, so the property name passes through unchanged
  (Engine/Source/Runtime/Engine/Public/Materials/MaterialExpressionSubstrate.h and
  Engine/Source/Editor/UnrealEd/Private/MaterialGraphNode.cpp).
- UMaterialExpressionNoise DOES override GetInputName() for its Position input: it returns
  GetWorldPositionInputName(WorldPositionOriginType), which for the default WorldPositionOriginType
  (Absolute) is "World Position" (with a space), not the property name "Position"
  (Engine/Source/Runtime/Engine/Private/Materials/MaterialExpressionNoise.cpp and MaterialShared.cpp).
- Every single-input node whose only FExpressionInput property is literally named "Input" (Abs, Frac,
  Length, OneMinus, Saturate, ComponentMask, ...) can't be targeted by the string "Input" either:
  UMaterialGraphNode::GetShortenPinName explicitly maps the pin name "Input" to NAME_None, and
  MaterialEditingLibrary's internal GetExpressionInputByName treats a None/empty ToInputName as "return
  the expression's first input" rather than "no match". So the correct dst_input for these nodes is the
  empty string "" (which also happens to be simpler and can't typo against a property name).

All three were found by running the script and reading the raised "failed to connect" error against the
engine source, exactly per this task's requirement to raise rather than silently skip.
"""
import unreal

VFX_DIR = "/Game/Shinobi/VFX"
MEL = unreal.MaterialEditingLibrary
TOOLS = unreal.AssetToolsHelpers.get_asset_tools()


def fresh_material(name):
    path = f"{VFX_DIR}/{name}"
    if unreal.EditorAssetLibrary.does_asset_exist(path):
        if not unreal.EditorAssetLibrary.delete_asset(path):
            raise RuntimeError(f"could not delete {path} (is it open in the editor?)")
    material = TOOLS.create_asset(name, VFX_DIR, unreal.Material, unreal.MaterialFactoryNew())
    if material is None:
        raise RuntimeError(f"failed to create {path}")
    material.set_editor_property("blend_mode", unreal.BlendMode.BLEND_ADDITIVE)
    material.set_editor_property("shading_model", unreal.MaterialShadingModel.MSM_UNLIT)
    material.set_editor_property("two_sided", True)
    return material


def node(material, cls, x, y, **props):
    expression = MEL.create_material_expression(material, cls, x, y)
    for key, value in props.items():
        expression.set_editor_property(key, value)
    return expression


def link(src, dst, dst_input, src_output=""):
    if not MEL.connect_material_expressions(src, src_output, dst, dst_input):
        raise RuntimeError(f"failed to connect {src.get_name()}.{src_output} -> {dst.get_name()}.{dst_input}")


def shared_params(material):
    color = node(material, unreal.MaterialExpressionVectorParameter, -1200, -300,
                 parameter_name="Color", default_value=unreal.LinearColor(0.15, 0.55, 1.0, 1.0))
    intensity = node(material, unreal.MaterialExpressionScalarParameter, -1200, -150,
                     parameter_name="Intensity", default_value=6.0)
    fade = node(material, unreal.MaterialExpressionScalarParameter, -1200, 0,
                parameter_name="Fade", default_value=1.0)
    # color * intensity * fade
    ci = node(material, unreal.MaterialExpressionMultiply, -1000, -250)
    link(color, ci, "A")
    link(intensity, ci, "B")
    cif = node(material, unreal.MaterialExpressionMultiply, -850, -200)
    link(ci, cif, "A")
    link(fade, cif, "B")
    return cif


def finish(material, emissive):
    """Substrate: emissive -> Unlit BSDF -> Front Material."""
    unlit = node(material, unreal.MaterialExpressionSubstrateUnlitBSDF, 200, 0)
    link(emissive, unlit, "EmissiveColor")
    if not MEL.connect_material_property(unlit, "", unreal.MaterialProperty.MP_FRONT_MATERIAL):
        raise RuntimeError(f"failed to connect Front Material on {material.get_name()}")
    errors = MEL.recompile_material(material)
    if errors:
        raise RuntimeError(f"{material.get_name()} failed to compile: {errors}")
    if not unreal.EditorAssetLibrary.save_loaded_asset(material):
        raise RuntimeError(f"failed to save {material.get_name()}")
    unreal.log(f"[setup_vfx] built: {material.get_path_name()}")


def build_aura():
    m = fresh_material("M_ChakraAura")
    tint = shared_params(m)
    uv = node(m, unreal.MaterialExpressionTextureCoordinate, -1400, 250, u_tiling=4.0, v_tiling=1.5)
    pan = node(m, unreal.MaterialExpressionPanner, -1200, 250, speed_x=0.0, speed_y=-1.2)  # flames rise
    link(uv, pan, "Coordinate")
    time = node(m, unreal.MaterialExpressionTime, -1200, 400)
    slow = node(m, unreal.MaterialExpressionMultiply, -1050, 400, const_b=0.7)
    link(time, slow, "A")
    pos = node(m, unreal.MaterialExpressionAppendVector, -900, 300)
    link(pan, pos, "A")
    link(slow, pos, "B")
    noise = node(m, unreal.MaterialExpressionNoise, -750, 300, scale=3.0, levels=3, output_min=0.0, output_max=1.0)
    # MaterialExpressionNoise overrides GetInputName() to return GetWorldPositionInputName(WorldPositionOriginType)
    # for its Position input; the default WorldPositionOriginType (Absolute) yields "World Position", not the
    # property name "Position" (Engine/Source/Runtime/Engine/Private/Materials/MaterialExpressionNoise.cpp and
    # MaterialShared.cpp's GetWorldPositionInputName). Confirmed the hard way: the naive "Position" name raised
    # "failed to connect ... -> MaterialExpressionNoise_0.Position" on the first run.
    link(pos, noise, "World Position")
    flame = node(m, unreal.MaterialExpressionPower, -600, 300, const_exponent=2.0)
    link(noise, flame, "Base")
    # Top fade: 1 at the bottom of the shell, 0 at the top. If the engine cylinder's V runs the other way,
    # the manual check (Task 5) flips this by swapping the OneMinus.
    v = node(m, unreal.MaterialExpressionComponentMask, -1200, 550, r=False, g=True, b=False, a=False)
    raw_uv = node(m, unreal.MaterialExpressionTextureCoordinate, -1400, 550)
    link(raw_uv, v, "")
    top_fade = node(m, unreal.MaterialExpressionOneMinus, -1050, 550)
    link(v, top_fade, "")
    fresnel = node(m, unreal.MaterialExpressionFresnel, -750, 550, exponent=2.5)
    rim = node(m, unreal.MaterialExpressionAdd, -600, 550, const_b=0.35)
    link(fresnel, rim, "A")
    shape = node(m, unreal.MaterialExpressionMultiply, -450, 350)
    link(flame, shape, "A")
    link(top_fade, shape, "B")
    shaped = node(m, unreal.MaterialExpressionMultiply, -300, 400)
    link(shape, shaped, "A")
    link(rim, shaped, "B")
    emissive = node(m, unreal.MaterialExpressionMultiply, -100, 0)
    link(tint, emissive, "A")
    link(shaped, emissive, "B")
    finish(m, emissive)


def build_ring():
    m = fresh_material("M_ChakraRing")
    tint = shared_params(m)
    uv = node(m, unreal.MaterialExpressionTextureCoordinate, -1400, 250)
    centred = node(m, unreal.MaterialExpressionSubtract, -1250, 250, const_b=0.5)
    link(uv, centred, "A")
    dist = node(m, unreal.MaterialExpressionLength, -1100, 250)
    link(centred, dist, "")
    radius = node(m, unreal.MaterialExpressionMultiply, -950, 250, const_b=2.0)  # 0 centre .. 1 edge
    link(dist, radius, "A")
    time = node(m, unreal.MaterialExpressionTime, -1250, 450)
    rate = node(m, unreal.MaterialExpressionMultiply, -1100, 450, const_b=1.2)
    link(time, rate, "A")
    pulse = node(m, unreal.MaterialExpressionFrac, -950, 450)  # 0..1 expanding
    link(rate, pulse, "")
    gap = node(m, unreal.MaterialExpressionSubtract, -800, 350)
    link(radius, gap, "A")
    link(pulse, gap, "B")
    gap_abs = node(m, unreal.MaterialExpressionAbs, -650, 350)
    link(gap, gap_abs, "")
    band = node(m, unreal.MaterialExpressionMultiply, -500, 350, const_b=8.0)  # ring width ~1/8
    link(gap_abs, band, "A")
    ring = node(m, unreal.MaterialExpressionOneMinus, -350, 350)
    link(band, ring, "")
    ring_sat = node(m, unreal.MaterialExpressionSaturate, -200, 350)
    link(ring, ring_sat, "")
    edge = node(m, unreal.MaterialExpressionOneMinus, -800, 550)  # fade toward the plane edge
    link(radius, edge, "")
    edge_sat = node(m, unreal.MaterialExpressionSaturate, -650, 550)
    link(edge, edge_sat, "")
    glow = node(m, unreal.MaterialExpressionMultiply, -500, 550, const_b=0.25)
    link(edge_sat, glow, "A")
    body = node(m, unreal.MaterialExpressionAdd, -350, 500)
    link(ring_sat, body, "A")
    link(glow, body, "B")
    shaped = node(m, unreal.MaterialExpressionMultiply, -200, 500)
    link(body, shaped, "A")
    link(edge_sat, shaped, "B")
    emissive = node(m, unreal.MaterialExpressionMultiply, -100, 0)
    link(tint, emissive, "A")
    link(shaped, emissive, "B")
    finish(m, emissive)


build_aura()
build_ring()
```

void UShinobiChakraAuraComponent::BeginPlay()
{
	Super::BeginPlay();
	if (IsNetMode(NM_DedicatedServer))
	{
		return; // purely cosmetic: nothing to render on a dedicated server, and no gameplay depends on it
	}

	UStaticMesh* Cylinder = LoadObject<UStaticMesh>(nullptr, CylinderPath);

	// Engine basic shapes are 100 uu across with the pivot at the centre; this component sits at the
	// capsule centre (192 uu tall), so -94 is just above the floor.
	InnerShell = AddPiece(TEXT("AuraInnerShell"), Cylinder, AuraMaterial, AuraMaterialPath, FVector(0.f, 0.f, 10.f), FVector(1.1f, 1.1f, 2.2f));
	OuterShell = AddPiece(TEXT("AuraOuterShell"), Cylinder, AuraMaterial, AuraMaterialPath, FVector(0.f, 0.f, 25.f), FVector(1.5f, 1.5f, 2.6f));
	AddPiece(TEXT("AuraGroundRing"), Plane, RingMaterial, RingMaterialPath, FVector(0.f, 0.f, -94.f), FVector(3.f, 3.f, 1.f));

	Light = NewObject<UPointLightComponent>(GetOwner(), MakeUniqueObjectName(GetOwner(), UPointLightComponent::StaticClass(), TEXT("AuraLight")));
	Light->SetupAttachment(this);
	Light->SetLightColor(Color);
	Light->SetAttenuationRadius(450.f);
	Light->SetCastShadows(false);
	Light->SetVisibility(false);
	Light->RegisterComponent();

	if (const IAbilitySystemInterface* Owner = Cast<IAbilitySystemInterface>(GetOwner()))
	{
		AbilitySystem = Owner->GetAbilitySystemComponent();
	}
	if (UAbilitySystemComponent* ASC = AbilitySystem.Get())
	{
		TagEventHandle = ASC->RegisterGameplayTagEvent(ShinobiTags::State_ChakraCharging, EGameplayTagEventType::NewOrRemoved)
			.AddUObject(this, &UShinobiChakraAuraComponent::OnChargingTagChanged);
		bCharging = ASC->HasMatchingGameplayTag(ShinobiTags::State_ChakraCharging);
	}
	SetComponentTickEnabled(bCharging);
	UpdatePieces();
}

void UShinobiChakraAuraComponent::EndPlay(const EEndPlayReason::Type EndPlayReason)
{
	if (UAbilitySystemComponent* ASC = AbilitySystem.Get())
	{
		ASC->UnregisterGameplayTagEvent(TagEventHandle, ShinobiTags::State_ChakraCharging, EGameplayTagEventType::NewOrRemoved);
	}
	for (UStaticMeshComponent* Piece : Pieces)
	{
		if (Piece)
		{
			Piece->DestroyComponent();
		}
	}
	Pieces.Reset();
	PieceMaterials.Reset();
	InnerShell = nullptr;
	OuterShell = nullptr;
	if (Light)
	{
		Light->DestroyComponent();
		Light = nullptr;
	}
	Super::EndPlay(EndPlayReason);
}

UStaticMeshComponent* UShinobiChakraAuraComponent::AddPiece(FName Name, UStaticMesh* Mesh, UMaterialInterface* Material, const TCHAR* MaterialPath, const FVector& Offset, const FVector& Scale)
{
	if (!Material)
	{
		ensureMsgf(false, TEXT("UShinobiChakraAuraComponent: missing material %s; skipping aura piece %s"), MaterialPath, *Name.ToString());
		return nullptr;
	}

	UStaticMeshComponent* Piece = NewObject<UStaticMeshComponent>(GetOwner(), MakeUniqueObjectName(GetOwner(), UStaticMeshComponent::StaticClass(), Name));
	Piece->SetupAttachment(this);
	Piece->SetStaticMesh(Mesh);
	Piece->SetRelativeLocation(Offset);
	Piece->SetRelativeScale3D(Scale);
	Piece->SetCollisionEnabled(ECollisionEnabled::NoCollision);
	Piece->SetGenerateOverlapEvents(false);
	Piece->SetCastShadow(false);

	UMaterialInstanceDynamic* Dynamic = UMaterialInstanceDynamic::Create(Material, this);
	Dynamic->SetVectorParameterValue(ColorParam, Color);
	Piece->SetMaterial(0, Dynamic);
	Piece->SetVisibility(false);
	Piece->RegisterComponent();

	Pieces.Add(Piece);
	PieceMaterials.Add(Dynamic);
	return Piece;
}

void UShinobiChakraAuraComponent::OnChargingTagChanged(const FGameplayTag Tag, int32 NewCount)
{
	bCharging = NewCount > 0;
	SetComponentTickEnabled(true); // fade in or out
}

void UShinobiChakraAuraComponent::TickComponent(float DeltaTime, ELevelTick TickType, FActorComponentTickFunction* ThisTickFunction)
{
	Super::TickComponent(DeltaTime, TickType, ThisTickFunction);
	Fade = FMath::FInterpConstantTo(Fade, bCharging ? 1.f : 0.f, DeltaTime, 1.f / FadeTime);
	Age += DeltaTime;
	if (InnerShell)
	{
		InnerShell->AddRelativeRotation(FRotator(0.f, SpinSpeed * DeltaTime, 0.f));
	}
	if (OuterShell)
	{
		OuterShell->AddRelativeRotation(FRotator(0.f, -SpinSpeed * DeltaTime, 0.f));
	}
	UpdatePieces();
	if (!bCharging && Fade <= 0.f)
	{
		SetComponentTickEnabled(false);
	}
}

void UShinobiChakraAuraComponent::UpdatePieces()
{
	const bool bShouldShow = Fade > 0.f;
	for (int32 Index = 0; Index < Pieces.Num(); ++Index)
	{
		Pieces[Index]->SetVisibility(bShouldShow);
		PieceMaterials[Index]->SetScalarParameterValue(FadeParam, Fade);
		PieceMaterials[Index]->SetScalarParameterValue(IntensityParam, Intensity);
	}
	if (Light)
	{
		// ponytail: two-sine flicker; swap for a curve asset if art direction wants a specific rhythm
		const float Flicker = 0.8f + 0.2f * FMath::Sin(Age * 23.f) * FMath::Sin(Age * 7.f);
		Light->SetVisibility(bShouldShow);
		Light->SetIntensity(LightIntensity * Fade * Flicker);
	}
}

**Code review (2026-09-25) found the retarget setup didn't match Epic's own reference flow and fixed it** — see `configure_retargeter()`'s docstring in the script for full detail; summary:
- **Chain mapping was `FUZZY`, causing a crumpled fist.** Manny's IK rig has per-finger metacarpal chains (`LeftIndexMetacarpal`, ...) that Mixamo has no counterpart for; fuzzy string-matching cross-wired them onto the finger chains instead of leaving them unmapped. Fixed to `EXACT` — matches Epic's own comment in `SRetargetAnimAssetsWindow.cpp`'s `FProceduralRetargetAssets::AutoGenerateIKRetargetAsset` ("use only exact chain mapping in the auto-retarget (default is fuzzy which can map toes to fingers and other chaos)"), which is what the in-editor "Auto Generate" button runs. Confirmed both skeletons' matching chains share canonical names (e.g. `get_source_chain("LeftArm")` → `"LeftArm"`).
- **The Run IK Rig op was left enabled**, the likely cause of arm/hand clipping — Epic disables it by default too ("auto-IK is not yet robust enough, still useful for manual editing though"). Now disabled via `set_retarget_op_enabled`.
- **Root Motion op left at its default `CopyFromSourceRoot`**, which is meaningless for Mixamo: its root-motion bone falls back to `Hips` (no separate root above the pelvis), so "copying root motion from the source root" was really just copying the pelvis. Now conditionally reconfigured to `GenerateFromTargetPelvis` + `SnapToGround` + `RotateWithPelvis` (matching Epic's own conditional: target has a separate root from its pelvis, but source's root *is* its pelvis) — confirmed via the op's own bone-reference getters rather than hardcoded. `AS_PowerUp` also gets `enable_root_motion=False` explicitly (a separate flag from the retarget op; controls in-game playback).
- **The retargeter's configuration and the batch retarget itself now re-run on every script run**, not just at creation, so this fix takes effect on an `RTG_MixamoToManny`/`AS_PowerUp` built by the old code. The batch retarget produces `AS_PowerUp` directly via `Search`/`Replace` (rather than a separate rename step), with `overwrite_existing_files=True` so `IKRetargetBatchOperation::OverwriteExistingAssets` reroutes existing references (e.g. `AM_ChakraCharge`'s slot track) onto the fresh result before deleting the old one.
- `verify_result()` now: samples bone rotation across the *whole* clip (not two points) and compares each target bone's deviation against the corresponding *source* Mixamo bone (so a naturally-still source bone isn't misread as a retarget bug); raises only if every sampled bone is static; reads section/slot names for real; and logs a first-vs-last-frame pelvis delta as a loop-seam indicator for Task 5.

- [x] **Step 4: Play the montage from the ability**

`GA_ChakraCharge.h` adds `TSoftObjectPtr<UAnimMontage> Montage` (`EditDefaultsOnly`, forward-declared `class UAnimMontage;`). `GA_ChakraCharge.cpp` sets it in the constructor to `/Game/Shinobi/Anims/AM_ChakraCharge.AM_ChakraCharge`, and in `ActivateAbility`, right after the successful `CommitAbility`, plays it and loops its `"Default"` section — but only once confirmed it's actually the ASC's current montage (a code-review fix: guards against looping a different, still-playing montage forever if `PlayMontage` ever silently failed):
```cpp
	if (UAnimMontage* Anim = Montage.LoadSynchronous())
	{
		UAbilityTask_PlayMontageAndWait* Play = UAbilityTask_PlayMontageAndWait::CreatePlayMontageAndWaitProxy(this, NAME_None, Anim);
		Play->ReadyForActivation();
		// Loop the montage's only section (AnimMontageFactory always names it "Default") while C is held;
		// PlayMontageAndWait's Activate() -> ASC->PlayMontage() runs synchronously above, so the ASC's
		// current montage should already be ours by the time this call runs. Guard on GetCurrentMontage()
		// still being Anim: if PlayMontage silently failed (e.g. no AnimInstance) the ASC's current montage
		// would be whatever was already playing (e.g. AM_Dodge), and looping *that* forever would be wrong.
		UAbilitySystemComponent* ASC = ActorInfo->AbilitySystemComponent.Get();
		if (ASC && ASC->GetCurrentMontage() == Anim)
		{
			static const FName LoopSection(TEXT("Default"));
			ASC->CurrentMontageSetNextSectionName(LoopSection, LoopSection);
		}
	}
```
Confirmed the factory-created montage's section is named `Default` (`EnsureStartingSection`) and that `CurrentMontageSetNextSectionName` is valid right after the task activates (`PlayMontageAndWait::Activate()` calls `ASC->PlayMontage()` synchronously, so `LocalAnimMontageInfo.AnimMontage` is already set by the time the guarded call above runs).
