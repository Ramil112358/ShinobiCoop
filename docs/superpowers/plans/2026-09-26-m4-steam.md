# ShinobiCoop M4 (Steam): Lean Plan

**Goal (spec §4 Menus; §6 Error handling; milestone M4):** main and pause menus, and hosting, finding, inviting and joining over Steam. It falls back to LAN (Null) without Steam, and handles failures and disconnects.

**Process:** lean, built inline with a light check at the end, then the user's playtest. Branch `feature/m4-steam`.

## Decisions

| Topic | Decision |
|---|---|
| Online stack | `OnlineSubsystemSteam` + `SteamSockets` (net driver, IP fallback), dev app ID 480. The engine falls back to the Null subsystem when Steam isn't running, and the menu then says "Steam not detected – LAN mode". `-nosteam` forces Null, which the smoke and shot scripts use (local IP connections). |
| Sessions | `UShinobiSessionSubsystem` (a `UGameInstanceSubsystem`) handles host, find, join and leave, plus accepting Steam invites. Sessions use lobbies and presence, allow 4 public connections and join-in-progress, and carry the key `SHINOBICOOP` so Find Games filters out other app-480 games. |
| Maps | A new `Lvl_MainMenu` (empty, `AShinobiMenuGameMode`: no pawn, menu widget). Host travels to `Lvl_ThirdPerson?listen` (arena mode). `Lvl_Combat` isn't used because it carries the template's enemy spawners; M5 builds the real arena. |
| Default map | **Deviation:** `GameDefaultMap` stays as the user set it (their uncommitted edit). A standalone launch opens the menu through `Scripts/play.ps1`, and returning to the menu goes through `UShinobiGameInstance::ReturnToMainMenu`, not `GameDefaultMap`. Set `GameDefaultMap=Lvl_MainMenu` before packaging. |
| Failures | Create, find and join failures appear on the menu. Network or travel failure (including "host left") → `ReturnToMainMenu`, and the menu shows the reason, which is kept on the subsystem across travel. A client leaving is already handled: its pawn is destroyed and the arena's wipe check ignores it. |
| Menus | Built in C++ like the HUD. Main menu: Host Game, Find Games (a list of sessions to join), Quit, a status line. Pause menu (Esc / Start): Resume, Invite Friend (Steam overlay), Leave. The game doesn't pause, since it's online. |

## Status (2026-09-26)

Built. All 49 automated tests and the M1 smoke test pass. The new `Scripts/smoke_m4.ps1` also passes: over LAN, a host hosts from the menu, a client finds and joins through the menu, the host quits, and the client lands back on the menu with the "Lost the connection" message.

On Steam, on the user's PC:
- The host's Steam session initialises, the lobby is created, and SteamSockets listens.
- A second process on the same PC can't start Steam (one instance per machine), falls back to LAN mode, and says so on the menu.

The real join test needs a second PC.

## Manual playtest

Run `Scripts/play.ps1` to launch the menu standalone. Steam only works outside PIE. `-Instances 2 -NoSteam` gives a local LAN pair.

| # | Check |
|---|---|
| 1 | The menu shows Host Game / Find Games / Quit. The status line says "Online via Steam" (or "Steam not detected - LAN mode" with `-NoSteam`). Mouse and gamepad both navigate it. |
| 2 | Host Game → the arena as a listen server (the wave countdown starts). |
| 3 | Second PC (another Steam account): Find Games lists "Join <host name> (1/4, N ms)". Joining brings them into the arena. |
| 4 | Steam invite: in-game Esc / Start → Invite Friend opens the Steam overlay. The friend accepts from Steam and joins automatically, even if their game is at the menu. |
| 5 | Pause menu: Resume closes it; the game never pauses. Leave → main menu. When the host leaves, the client lands on the menu with "Lost the connection...". |
| 6 | A client leaving mid-wave: their character disappears, and the host keeps playing (no false wipe). |
| 7 | A LAN pair (`-Instances 2 -NoSteam`): host on one, Find + Join on the other. |

Before packaging: set `GameDefaultMap=/Game/Shinobi/Maps/Lvl_MainMenu`. Esc in PIE stops PIE, so use Start (or play standalone) for the pause menu there.
